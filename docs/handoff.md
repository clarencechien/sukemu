# Handoff — Sukemu すける

給接手的 Claude Code。標記為**決策**的照做,標記為**陷阱**的不要重踩。互動原型已存在(`acetate-lens.html`),那是**互動與視覺的規格書**,不是可上線的程式碼——座標是手工量的,沒有後端。

---

## 1. 一句話

拍一張照或上傳一張圖,Sukemu 把上面的外文翻成台灣正體中文,**用一層透明標註疊回原圖上**——不重繪、不遮蔽,按住就能看原圖。

命名:**透ける**(sukeru,穿透、透明)+ mu。與 [manemu](https://manemu.ai-apps.work/) 同一個命名家族與產品家族。

## 2. 定位

**參考性翻譯**,不是保真翻譯。目標素材:標語、海報、菜單、展覽說明、資訊圖。

**明確不做**(不要自行擴張):
- 即時相機取景疊加(不是 AR camera,是拍完再看)
- 全圖重繪 / 修圖
- 直排文字與手寫辨識(v1 不處理,見 §11)
- **漫畫**——技術上可行,但著作權風險最高。不放進 UI、不放進行銷素材
- 公開分享頁面 / 譯文索引(見 §9)

## 3. 使用者流程

1. Google 登入(封測期間比對受邀名單,與 manemu 相同機制)
2. 拍照 或 從相簿選圖 或 貼上
3. 上傳 → 處理中(顯示進度階段,見 §5)→ 結果
4. **A 疊字**:譯文疊在原文位置上,按住看原圖
5. **C 註解**:圖上只留編號錨點,下方是編號註解欄(譯文/原文/譯註),可篩「有譯註」「待複核」
6. 譯文可就地編輯,存回本機

**品質優先於速度。** 使用者已經接受「拍完等一下」的心智模型,不要為了搶秒數犧牲解析度或關掉 thinking。目標是 5–10 秒出結果,**不是 2 秒**。

## 4. 技術決策

| 項目 | 決策 | 備註 |
|---|---|---|
| 前端 | Vanilla TS + Vite,無框架 | 單頁,引入框架只是負擔;原型已是這個形狀 |
| 部署 | Cloudflare Workers + Workers Assets | 與 manemu 同一套,push 即部署 |
| 認證 | Google OIDC + 受邀名單 + Turnstile | 直接沿用 manemu 的實作 |
| 暫存 | R2(僅處理期間)| **處理完立即刪除**,見 §9 |
| 結果保存 | **裝置端 IndexedDB** | 伺服器不留譯文 |
| 配額 | Durable Object,每人每日張數上限 | 同 manemu 的錢包保險絲思路 |
| 模型 | `gemini-3.5-flash` | 與 kvsplayer 一致;視覺理解夠強、成本可接受 |
| 正體中文 | OpenCC `cn→twp` 收尾 | 沿用 manemu / kvsplayer 的做法 |

**陷阱**:CF Workers 沒有 Node 內建模組。Gemini 走 REST(`generateContent`),不要用官方 Node SDK。

## 5. Gemini 呼叫規格

### 兩趟制(決策)

沿用 kvsplayer 的架構。第二趟不吃圖,成本約第一趟的 3%,失敗重試不用重付影像 token。

**P1 — 視覺趟**
- `media_resolution: HIGH`,thinking 打開
- 一次輸出:文字塊座標 + 原文 + 初譯 + 版面信心
- 這一趟**不產譯註**,避免輸出膨脹拖長延遲

**P2 — 文字趟**
- 只餵 P1 的 JSON(不含影像)
- 用語在地化(台灣正體、去除翻譯腔)、術語一致化、**產生譯註**
- 可以用比 P1 更強的模型:輸入只有一兩千 token,用 Pro 級的成本可以接受

### 分塊高解析度(決策)

菜單與資訊圖的小字在整張縮到 1024px 時會糊。**當偵測到文字塊數 > 15 或平均塊高 < 2%(正規化)時,把圖切成 2×3 重疊分塊,各自跑 P1 再合併座標。** 這是純粹用時間換品質,而這個產品願意換。

合併時以重疊區的文字內容做去重,不要靠座標判斷(分塊邊界會切斷文字塊)。

### Meta 注入(決策)

以下若可取得就放進 P1 的 prompt,對辨識品質幫助很大:

- **GPS → 國家/城市**:給語言先驗與在地詞彙(地方菜名、店家慣用語)
- **同一次階段的前幾張圖**:使用者連拍招牌→菜單→菜色時,前面確認過的詞彙當作本次的偏置詞表
- 拍攝時間(早餐/晚餐時段的菜單分區)

**後者是這個產品的結構性優勢:Lens 是無狀態的,做不到跨照片累積。** 用 session id 把同一次拍攝的詞彙串起來,第三張圖的品質會明顯優於第一張。

### 進度分段

處理要有可見的階段,不要只轉圈:`上傳中 → 讀取版面 → 翻譯 → 在地化`。分塊時顯示 `讀取版面 2/6`。

## 6. 資料契約

前端已經按這個形狀寫好,**請維持欄位名不變**:

```ts
type Block = {
  x: number; y: number; w: number; h: number;  // 正規化 %,相對原圖 natural size
  fs: number;      // 字級,單位 u(u = 圖片顯示寬度 / 100)
  c: number;       // 版面信心 0–1,< 0.9 前端會標「待複核」
  en: string;      // 原文(欄位名沿用,實際是來源語言)
  zh: string;      // 譯文
  nt?: string;     // 譯註,P2 產出,可無
};
type Result = { name: string; lang: string; blocks: Block[] };
```

**座標一律用正規化百分比,絕不用 CSS 像素。** 縮放、旋轉、換裝置時框才跟得住。

`fs` 由模型估或由框高反推——**實測後選一個,不要兩者混用**。原型是模型給值。

## 7. 前端行為(原型已實作,照抄)

- **A 疊字**:毛玻璃底(`backdrop-filter: blur + saturate(.55) + brightness(1.16)`)壓暗原圖讓標註浮起,譯文是高彩度橘紅加白色光暈,四角 HUD 括號。**強度可調滑桿(0–0.6,預設 0.30)**
- **C 註解**:圖固定在上方不捲動,註解欄自己有捲軸;選取項用 `order:-1` + `position:sticky` 頂到列首——**不要用 scrollIntoView,會造成畫面跳動**
- **按住看原圖**:按鈕、長按圖片、或按住 `O` 鍵。整層帶位移與模糊淡出,是「掀起」不是「關掉」
- **篩選**:全部 / 有譯註 / 待複核。當前選取項即使被濾掉也強制顯示
- **縮放滑桿**:圖片尺寸由 JS 計算後寫入 `style.width`

**陷阱**:不要用 `max-width:100%` 讓 CSS 決定圖片尺寸。在彈性/格線容器裡它會跟容器寬度互相依賴、解不開,圖片會塌成幾十像素。原型踩過,已改成 JS 算。

## 8. 視覺

### 與 manemu 的家族關係
同構:產品名 + 假名副標、一段解釋命名由來的文案、Google 登入等候名單、分頁式模式切換、單一飽和主色。
**差異:manemu 是紅(`#C0392B`),Sukemu 是青。** 兄弟產品,不同色。

### Tokens
```
--room:#0E1319  --panel:#151C25  --edge:#233240
--pale:#B9C9D8  --mute:#6C8296
--cool:#41C9FF   /* 品牌與 HUD。theme-color 用這支 */
--hot:#FF4A14    /* 譯文專用,紀律:只有譯文是這個顏色 */
```

字體:chrome 用 `IBM Plex Sans Condensed`,數據用 `IBM Plex Mono`,譯文與譯註用 `Noto Sans TC` 700。

**紀律**:橘紅只給譯文。不要拿去做按鈕、標題、裝飾。使用者要能一眼分辨「哪些字是 Sukemu 加上去的」。

## 9. 隱私與著作權立場(決策,不要改)

翻譯在著作權法上是**改作**,不是單純重製,改作權是著作財產權人專有的。所以架構上要站在「工具」而不是「內容服務」那一邊:

- 原圖只在處理期間存在 R2,**完成即刪**
- **譯文不落地在伺服器**,只回傳給該使用者,存在他的裝置
- **不做公開分享連結、不做譯文索引**
- 服務條款寫明:使用者自行上傳、結果僅供其個人參考
- 準備通知取下的聯絡管道

這幾條同時也是隱私賣點,寫進登入頁。

## 10. 里程碑

1. **M1 靜態骨架** — 把原型接上 Vite,拆成模組,假資料驅動。無後端
2. **M2 上傳與 P1** — Worker 端 REST 呼叫 Gemini、結構化輸出、真實座標渲染。**這一步驗證框準度,見 §12**
3. **M3 P2 與譯註** — 文字趟、在地化、OpenCC、C 註解模式接真資料
4. **M4 認證與配額** — Google OIDC、受邀名單、Turnstile、DO 配額、R2 生命週期
5. **M5 PWA** — manifest、Service Worker、離線殼、`viewport-fit=cover`、iOS 安裝流程
6. **M6 分塊與 Meta** — 高解析分塊、GPS、session 詞彙累積

M2 是分水嶺。框不準的話後面全都不用做。

## 11. 已知未解

- **直排文字**:日文招牌、中文對聯。需要模型回報方向,前端用 `writing-mode: vertical-rl`。v1 先偵測到就標「不支援」,不要靜默做錯
- **手寫**:不處理
- **透視變形**:斜拍的招牌用矩形框會歪。真正的解法是讓模型回四角座標(quad)餵給 `transform: matrix3d`。v1 用矩形,先量誤差有多大
- **中譯外的文字膨脹**:目前方向是外譯中(通常縮短)所以還好。反向要處理溢出策略

## 12. 驗收

- [ ] **框準度**:十張真實照片(三招牌、三菜單、二海報、二展場說明),人工標註後量 IoU。**這是最重要的一項,M2 就要做**
- [ ] 手機 Safari 與 Chrome 都能安裝 PWA,離線可開殼
- [ ] 拍照到結果 ≤ 10 秒(單張,未分塊)
- [ ] 疊字在淺背景與深背景上都清晰可讀
- [ ] 按住看原圖:按鈕、長按、鍵盤三種入口都有效
- [ ] 註解模式選取任一則,圖片位置完全不動
- [ ] 譯文編輯後同步更新圖上與註解欄
- [ ] R2 中的原圖在處理完成後確實被刪除
- [ ] 單日配額觸頂時有明確提示,不是靜默失敗

## 13. 開工前先確認

1. **P2 用哪個模型?** 輸入小,值得用 Pro 級。跑一次 A/B 再定。
2. **分塊的觸發門檻**要實測調,§5 給的數字是起點不是結論。
3. **GPS 要不要在 v1 就做?** 會觸發權限詢問,可能傷首次體驗。建議 v1 先不做,M6 再加並做成選用。
